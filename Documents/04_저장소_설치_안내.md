# 새 환경에서 프로젝트 열기

현재 저장소는 GoDeep의 기획 문서, 직접 작성한 코드·씬·프리팹과 Unity 설정을 보관한다. 다운로드한 Photon SDK와 App ID 설정, Unity 캐시·로그·임시 백업은 Git에서 제외한다. 현재 PC에 설치된 SDK와 입력된 App ID는 그대로 유지된다.

## 필수 환경

- Unity **6000.6.0f1**. Packages의 manifest와 lock 파일로 URP·Input System 등을 복원한다.
- Photon **Fusion 2.1.3 / build 2390**.
- Photon **Voice 2.63 Realtime5**. Realtime4/PUN용 일반 Voice 패키지를 섞지 않는다.

## 최초 설치

1. 저장소를 복제하고 지정 Unity 버전으로 연다.
2. Photon 공식 다운로드에서 위 버전의 `.unitypackage` 두 개를 받는다.
3. 비어 있는 `Assets/Photon` 환경에서는 **Voice Realtime5를 먼저**, **Fusion 2.1.3을 마지막에** 가져온다. 이 조합에서 공유 Photon Realtime과 PhotonClient는 Fusion 패키지의 **5.1.20**을 유지한다. 두 패키지 설치가 끝나기 전 일시적 컴파일 오류가 생길 수 있다.
4. Fusion Hub에서 Fusion App ID와 Voice App ID를 로컬 `PhotonAppSettings`에 입력한다. App ID는 이 문서나 코드에 넣지 않는다.
5. NetworkProjectConfig의 `AssembliesToWeave`에 `Assembly-CSharp`, `Assembly-CSharp-firstpass`, `PhotonVoice.Fusion`이 포함됐는지 확인한다. Voice의 편집기 도우미도 등록을 수행한다.
6. Unity 6000.6에서 ARMv7 플러그인의 오래된 Importer 메타 경고가 발생하면 `Tools/ConfigurePhotonSdk.cs`의 `ConfigurePhotonSdk.configure`를 Unity Pipeline `run_script`로 실행한다. 기존 GUID와 App ID를 보존한 채 두 네이티브 플러그인의 Importer 형식을 현재 버전으로 맞춘다.
7. 컴파일 완료 후 `Assets/1. Scenes/Home.unity`를 열고 실행한다.

서로 다른 SDK를 이미 섞어 설치한 경우 위 순서로 덮어쓰기만 해서는 중복 `.asmdef`나 이전 DLL이 남을 수 있다. 먼저 Photon 폴더와 로컬 설정을 프로젝트 밖 임시 백업에 보존하고 깨끗한 SDK 폴더에서 복원한다. 현재 작업 PC에서는 이미 이 복구가 완료됐다.

## 편집기 도구

`Tools/Invoke-UnityPipeline.ps1`은 실행 중인 Unity의 로컬 Pipeline에 접속한다. 토큰은 Unity가 제공한 로컬 연결 파일에서 읽고 출력하지 않는다. 일반 게임 실행에 이 도구나 Codex는 필요하지 않다.

```powershell
./Tools/Invoke-UnityPipeline.ps1 -Command run_script -ParametersJson '{"file":"Tools/ConfigurePhotonSdk.cs","entry":"ConfigurePhotonSdk.configure"}'
```

SDK와 설정을 재설치했다면 실제 컴파일·씬 로딩·온라인 접속을 다시 확인한다. 설치 문서만으로 새로운 환경에서의 검증이 완료되는 것은 아니다.
