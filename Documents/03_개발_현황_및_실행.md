# 개발 현황 및 실행 안내

갱신: 2026-09-28 · M1 로컬 시제품 + M2 온라인 이동 증분

## 현재 결과

기획서와 **로컬 조작 시제품**, 이어서 **Fusion 최대 4인 접속·이동 시험**을 프로젝트에 반영했다. 기존 Home·StandBy·Play 씬에 화면과 동작을 연결했으며 로컬·온라인 플레이어 프리팹도 저장했다. 별도로 사용자가 Inspector 참조를 연결할 필요는 없다.

| 항목 | 상태 |
|---|---|
| 기획서 / 개발 계획 | 작성 완료 |
| Home → StandBy → Play | 로컬 연습 진입 연결 완료 |
| 1인칭 수영·시점·벽 충돌 | 구현 및 플레이 모드 검증 |
| 워치·깊이·산소 표시 | 구현. 빈손 우클릭 유지 |
| 워치 신호 | 로컬 미리보기. 네트워크 전송은 아직 없음 |
| 산소팩 자신/동료 사용 | 구현. 동료는 움직이지 않는 연습용 다이버 |
| 에어포켓 / 보급 | 소모 중단과 장치 사용 분리 |
| 행동불가·산소 구조·탈락 | 상태 로직 구현·검증. 실제 협동 구조는 M2 |
| 아이템 부활 / 팀 관전 / 에어포켓 팀 부활 | 아직 미구현 |
| 팔·장비 표현 / 효과음 | 기본 도형과 절차적 동작, 짧은 합성 피드백 소리 |
| 목표 도착 / 재시작 | 구현 및 검증 |
| Fusion 접속·이동 | Shared 모드 방 생성·코드 입장·퇴장, 독립 프로세스 4인 이동 확인 |
| 온라인 산소·아이템·구조·워치 신호 | 다음 증분. 현재 온라인 시험은 이동만 지원 |
| Photon Voice | 호환 SDK 설치 완료. 실제 통화는 아직 미구현 |
| 3개 챕터 / 모래·물살·수직 미로 | 아직 미구현 |

M1 전체를 완료한 것은 아니다. 다음에는 사용자의 조작감 평가를 반영하고 1인칭 손·전신 모델과 애니메이션을 구체화한다. 현재 동굴은 기능을 확인하는 짧은 테스트 구간이며 5~15분짜리 정식 챕터가 아니다.

## 실행 순서

1. Unity에서 `Assets/1. Scenes/Home.unity`를 연다.
2. Unity 상단 Play 버튼을 누른다.
3. **PREPARE TO DIVE** → **START LOCAL PRACTICE**를 선택한다.
4. 안내 화면에서 **DIVE / RESUME**를 누르고 Game 뷰를 조작한다.
5. 청록색 경로 표식을 따라가며 장비를 시험하고, 끝의 따뜻한 조명 구역에 도착한다.

Play 씬을 직접 열어 실행해도 된다. 다른 창으로 포커스를 옮기면 일시정지하며, 돌아와 **DIVE / RESUME**로 재개한다. 게임 화면의 영문은 기본 내장 폰트를 사용하는 임시 UI다. 한글 UI와 배포용 글꼴은 후속 UI 작업에서 적용한다.

온라인은 StandBy 오른쪽의 **CREATE ROOM** 또는 코드 입력 후 **JOIN ROOM**으로 진입한다. 최대 4명, 지역은 asia다. 온라인에서 산소는 고정되고 아이템·구조·워치 신호·음성은 아직 작동하지 않는다. Esc는 자기 이동만 멈추며 **LEAVE ROOM**으로 퇴장한다. 자세한 권한 구조·실행·검증은 [Fusion 온라인 개발 기록](05_Fusion_온라인_개발.md)을 따른다.

| 입력 | 동작 |
|---|---|
| 마우스 / WASD | 시점 / 수영 |
| Space / 왼쪽 Ctrl | 상승 / 하강 |
| 왼쪽 Shift | 빠른 수영 |
| 빈손 + 우클릭 유지 | 워치 확인 |
| 워치 확인 중 1 / 2 / 3 / 4 | 따라와 / 기다려 / 도움 필요 / 산소 부족 신호 미리보기 |
| Q | 산소팩 장착 또는 빈손 전환 |
| 산소팩 + 좌클릭 | 자신에게 산소 사용 |
| 산소팩 + 우클릭 | 3m 이내 조준한 연습 다이버에게 산소 사용 |
| E | 산소팩 획득 또는 산소 공급 장치 사용 |
| Esc / R | 일시정지 / 처음부터 재시작 |

입구에서는 산소가 가득 차 있으므로 자신에게 산소팩을 써도 소모되지 않는다. 물속에 나가 산소를 사용한 뒤 시험한다. 연습 다이버는 산소 25%에서 대기하며 자동 이동이나 자동 구조를 하지 않는다. 산소팩은 +35, 최대 3개다.

## 이번 검증

Unity 6000.6.0f1의 실제 플레이 모드에서 30개 동작 검사를 통과했다. 입력은 자동 검사 중 플레이어의 입력 프레임 진입점으로 전달했고, 메뉴 전환은 저장된 실제 버튼 이벤트를 실행했다. 물리 충돌과 레이캐스트, 씬 이동은 실제 Unity 실행 상태에서 확인했다.

손목·UI 수정 후 재컴파일도 성공했다. 최종 확인 시 컴파일 실패 없음, 현재 Unity 콘솔 오류 0개였으며 검증 플레이를 종료하고 Home 씬을 열어 두었다. 과거 SDK 설치 때 발생했던 오류 로그 이력과 현재 상태는 구분한다.

- Home → StandBy → Play 버튼 참조와 비동기 이동.
- 초기 산소·소지품·에어포켓 상태.
- 가득 찬 산소통, 사거리 밖 대상, 벽 너머 대상에 대한 소모 방지.
- 자기 사용·동료 사용의 산소 효과와 1회 소모, 소지 수량 제한.
- 빈손 워치, 손 상태에 따른 우클릭 분리, 신호 선택, 버튼 해제.
- 에어포켓에서 소모만 멈추고 장치 사용으로 충전되는 흐름.
- 프레임 분할에 따른 산소 소모 일관성.
- 행동불가 유예, 산소 구조, 유예 종료 후 탈락 상태.
- 동굴 벽 충돌, 3축 대각선 입력 속도 제한.
- 씬 스크립트 누락 없음, 플레이어 프리팹 저장.
- 물속을 거친 뒤 목표 에어포켓 도착과 재시작 초기화.

Home·StandBy·Play·워치·도착 화면은 Unity 카메라와 UI를 함께 렌더링해 확인했다. 화면 확인 과정에서 손목 가림과 진행 표시를 수정했다. 자동 검사는 실제 사람이 느끼는 조작감·소리 품질·멀미를 판정하지 않는다.

**추가 검증:** Windows 개발 빌드 성공. 같은 PC의 에디터 1개와 실행 파일 3개가 실제 Photon Cloud에서 이동·회전을 교환했다. 5번째 입장 거절, 생성자 퇴장 후 3인 유지, 일반 퇴장과 실패 후 새 연결도 확인했다. 온라인 안내 수정 후 로컬 30개 검사도 다시 통과했다.

**미실행 검증:** 최종 배포 빌드, 서로 다른 실제 PC, 마이크 송수신, 지연·패킷 손실·장시간 복구, 실제 리그 애니메이션. 이번 결과로 협동 생존 게임 전체나 출시 준비가 완료됐다고 판단하면 안 된다.

## 파일과 조절 위치

| 위치 | 용도 |
|---|---|
| `Assets/2. Scripts/Player` | Player와 입력·수영·산소·아이템·워치·표현 Component |
| `Assets/2. Scripts/World` | 에어포켓과 보급 장치 |
| `Assets/2. Scripts/Flow` | 씬 이동과 연습 진행 |
| `Assets/2. Scripts/UI` | 플레이 상태 표시 |
| `Assets/3. Prefabs/Prototype/Diver.prefab` | 연결된 로컬 다이버 프리팹 |
| `Assets/6. Data/Prototype` | 테스트 동굴 메시와 재질 |
| `Tools/GoDeepPrototypeBuilder.cs` | 빈 초기 씬에 시제품을 만드는 편집 도구 |
| `Tools/GoDeepPrototypePolish.cs` | 확인된 손목·UI 표시 보정 |
| `Tools/GoDeepPrototypeValidation.cs` | 실제 플레이 모드 검사와 화면 확인 도구 |
| `.utmp/prototype-20260928` | 원본 씬 백업, 검사 결과 JSON, 확인 화면 |

`Diver`의 Inspector에서 `PlayerMovementComponent`의 속도·가감속·감도, `PlayerOxygenComponent`의 산소·소모·구조 시간, `PlayerItemComponent`의 소지량·회복량, `PlayerPresentationComponent`의 팔 움직임 강도를 조절할 수 있다. 씬의 `PrototypeSession`에는 로컬 플레이어·연습 다이버·에어포켓이 연결돼 있다.

생성 도구는 기존 작업을 덮어쓰지 않도록 이미 시제품이 있으면 중단한다. 현재 씬을 초기 생성 도구로 다시 만들 필요는 없다. 검증 도구는 **Home에서 플레이 모드를 시작한 상태**에만 전체 검사를 실행하며, 끝나면 시제품이 새로 시작된 일시정지 상태로 남는다. 일반 실행에는 `Tools`가 필요하지 않다.

## 다음 작업

사용자의 조작감 평가와 모델·모션 자산 결정은 M1 후속 작업으로 남긴다. 그와 독립적으로 M2의 온라인 산소·아이템·구조·워치 신호를 이어서 구현한다. 에어포켓별 음성 정책은 해당 생존 상태 동기화 이후에 연결한다.
