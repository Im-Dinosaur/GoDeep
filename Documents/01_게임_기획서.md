# GoDeep 게임 기획서

작성일: 2026-09-28 · 버전: 0.1 · 상태: 시제품 개발 기준

이 문서는 「게임 아이디어 비교」 대화의 최신 결정을 우선한다. 이전의 보물 판매형, 음성채팅 제외, 챕터당 30분 구상은 현재 기준에서 제외했다. **확정**은 사용자가 선택한 방향이고, **초기 설계안**과 **시제품 수치**는 플레이 결과에 따라 바꾼다.

## 1. 게임의 중심

최대 4명의 친구가 좁고 어두운 블루홀 내부 동굴에서 산소를 관리하고 서로를 도우며 최종 탈출구에 도달하는 3D 1인칭 협동 탐험 게임이다. 목표는 보물 판매나 장비 성장보다 **친구가 일으킨 사고를 함께 수습하고 다음 안전지대에 도착하는 경험**이다.

| 항목 | 기준 |
|---|---|
| 작업명 | GoDeep — 최종 상품명은 별도 결정 |
| 플랫폼 | PC / Steam 목표. 현재 시제품은 Windows 키보드·마우스 기준 |
| 인원 | 최대 4인 협동. 마지막 생존자 한 명도 필수 경로 통과 가능 |
| 시점 | 3D 1인칭. 동료에게 보이는 전신 표현도 최종 범위에 포함 |
| 배경 | 블루홀 내부의 침수 동굴 |
| 분위기 | 어둡고 음산한 동굴, 과장되고 장난스러운 캐릭터 |
| 구성 | 초기 3개 챕터. 추후 추가 가능 |
| 시간 | 챕터당 5~15분. 탐색·협동을 포함한 초회 성공 목표 |
| 소통 | 같은 에어포켓에서 음성 + 워치, 수중에서는 워치 |
| 네트워크 | Photon Fusion 2.1 + Photon Voice |
| 에셋 구매 예산 | 50,000원. 실제 구매는 자산·라이선스·가격 확인 후 별도 결정 |

개발 기간은 현재 계획상 16~24주이며 약 5개월을 목표로 한다. 실제 작업 속도를 측정한 납기 약속이 아니며 첫 시제품의 조작감·연출·멀티 검증 후 재산정한다. 위협 생물, 전투, 경제 시스템은 초기 제작 범위에 포함하지 않는다.

## 2. 핵심 경험과 한 판의 흐름

1. **Home**: 게임 진입과 메뉴.
2. **StandBy**: 친구들과 합류하고 준비. 출시 버전에서는 방 생성·입장·준비 상태를 담당한다.
3. **Play**: 에어포켓에서 장비를 확인하고 잠수한다.
4. 동굴의 길과 위험을 판단하고, 워치로 신호를 보내며 산소를 사용한다.
5. 동료에게 산소를 공급하거나 탈락한 동료를 부활시킨다.
6. 챕터 끝의 에어포켓에서 다시 만나 부활·산소 보급·대화를 진행한다.
7. 마지막 챕터를 통과하면 최종 탈출. 전멸 시 새 도전을 시작한다.

**전멸 시 입구부터 재도전**은 이전 대화에서 제안된 초기 규칙이다. 에어포켓은 팀 복구 거점이며 저장 체크포인트와 구분한다. 장기 저장, 중도 참가, 재접속, 호스트 이탈 처리의 최종 정책은 멀티 시제품 단계에서 확정한다.

## 3. 이동과 조작

수영은 빠르게 반응하면서도 가속·감속으로 물속의 느낌을 표현한다. 손목을 보거나 아이템을 사용하는 중에도 이동할 수 있다. 과장된 팔·몸 동작이 조작 반응을 늦추지 않게 한다.

| 입력 | 동작 | 결정 상태 |
|---|---|---|
| 마우스 이동 | 시점 회전 | 시제품 배치 |
| W / A / S / D | 바라보는 방향 기준 수영 | 시제품 배치 |
| Space / Ctrl | 상승 / 하강 | 시제품 배치 |
| Shift | 빠른 수영 | 시제품 배치 |
| 빈손 + 우클릭 유지 | 워치 확인 | 사용자 결정, 유지 방식은 초기 설계안 |
| 아이템 + 좌클릭 | 자신에게 사용 | 사용자 결정 |
| 아이템 + 우클릭 | 조준한 동료에게 사용 | 사용자 결정 |
| Q | 아이템과 빈손 전환 | 초기 설계안 |
| E | 보급품 획득 / 장치 사용 | 시제품 배치 |
| 워치 확인 중 1~4 | 팀 신호 선택 | 초기 설계안 |
| Esc | 시제품 일시정지 / 마우스 해제 | 시제품 기능 |
| R | 시제품 다시 시작 | 시제품 기능 |

빈손 좌클릭의 별도 게임 행동은 아직 정하지 않았다. 아이템을 상대에게 **사용하는 것**과 물건 자체를 **전달하는 것**은 구분한다. 물건 전달은 추후 필요성을 확인한다.

## 4. 산소, 구조, 부활

- 각 플레이어가 개인 산소를 보유한다. 수중에서 소모하며 워치에서 잔량을 확인한다.
- 에어포켓에서는 산소 소모를 멈춘다. 산소통 충전은 공급 장치를 사용하는 별도 행동으로 둔다.
- 산소 0에서 바로 제거하지 않고 구조 가능한 행동불가 상태를 둔다.
- 제한 시간 내 산소를 받으면 복귀한다. 구조받지 못하면 탈락하고 관전한다.
- 휴대용 산소팩은 자신 또는 가까운 동료에게 사용할 수 있다.
- 부활 아이템과 에어포켓 부활 장치를 최종 게임 범위에 포함한다.
- 유효한 대상이 없거나 효과가 없는 사용에는 아이템을 소비하지 않는다. 클릭 한 번당 한 번만 사용한다.
- 필수 생존 물자는 운만으로 부족해지지 않도록 배치한다.

행동불가 제한 시간, 부활 시 지급 산소, 장치 사용 횟수, 소모품 수량은 밸런스 검증 항목이다. 한 에어포켓의 부활 장치를 도전당 한 번만 쓰는 규칙은 초기 제안이며 아직 확정값이 아니다.

### 첫 시제품의 임시 값

| 항목 | 시작값 |
|---|---:|
| 최대 산소 | 100 |
| 기본 소모 | 초당 0.55 |
| 빠른 수영 소모 배율 | 1.25 |
| 산소팩 충전 | 35 |
| 초기 / 최대 산소팩 | 2 / 3 |
| 행동불가 유예 | 20초 |
| 동료·장치 상호작용 거리 | 3m |

이 값은 짧은 조작 시험용이며 최종 챕터 난이도를 의미하지 않는다. 산소 압박과 구조 기회가 어느 정도로 느껴지는지 먼저 확인한다.

## 5. 워치와 소통

워치는 현재 깊이(m), 산소(%), 최근 신호를 표시한다. 깊이는 해수면 기준이며 지하 에어포켓에서도 깊이 수치 자체는 유지된다. 시야 중앙을 계속 숫자로 채우지 않고 손목을 들어 정보를 읽는 행동을 중심으로 한다.

초기 신호는 `따라와 / 기다려 / 도움 필요 / 산소 부족`의 네 가지다. 최종 버전에서는 보낸 사람, 신호, 수신 시점을 알 수 있어야 한다. 워치를 내리고 있어도 알림음으로 수신을 인지하고, 산소 위험 알림은 별도로 제공한다.

| 두 플레이어의 상태 | 인게임 음성 |
|---|---|
| 같은 에어포켓 | 허용 |
| 서로 다른 에어포켓 | 차단 |
| 둘 다 수중 | 차단 |
| 한 명만 수중 | 차단 |

외부 통화 사용을 막으려 하지 않는다. 말을 못 해야만 풀리는 퍼즐에 재미를 의존하지 않는다. 에어포켓 입출입 시 음성 송신과 수신 정책을 함께 검증한다.

## 6. 챕터 설계안

아래 이름과 기믹 배치는 대화에서 제안된 제작 기준안이다. 챕터 수와 길이는 사용자 결정이지만 실제 배치와 명칭은 플레이 검증 후 확정한다.

| 챕터 | 목표 시간 | 중심 기믹 | 협동 상황 |
|---|---:|---|---|
| 1. 퇴적 동굴 | 5~8분 | 빠른 움직임으로 발생하는 모래 구름 | 친구가 흐린 시야에서 불빛과 워치로 재집결 |
| 2. 급류 수로 | 8~12분 | 강약이 반복되는 구역별 물살 | 이동 타이밍 판단, 흩어진 동료 합류 |
| 3. 심층 수직 미로 | 10~15분 | 여러 깊이에서 교차하는 통로 | 깊이·지형·표식으로 길을 찾고 앞선 기믹 종합 |

세 챕터의 성공 플레이 합계 목표는 **23~35분**이며 에어포켓 대화·재정비와 재도전은 별도다. 숙련자의 단축 완주는 허용한다. 각 챕터는 도입 → 응용 → 가장 긴장되는 구간 → 에어포켓 순으로 구성한다.

긴 복도나 기다림으로 시간을 채우지 않는다. 좁은 통로 앞뒤에는 비켜서거나 구조할 공간을 마련한다. 여러 사람이 동시에 조작해야만 열리는 필수 문은 마지막 생존자의 전진을 막으므로 넣지 않는다.

## 7. 그래픽·애니메이션·소리

- 배경은 청록·남색의 낮은 조도, 안전지대는 따뜻한 조명으로 구분한다. 갈림길에는 읽을 수 있는 지형 단서를 둔다.
- 캐릭터의 발차기·기울기·허둥대는 손짓은 과장한다. 공포와 친구들의 장난스러운 행동이 함께 나타나게 한다.
- 1인칭 손과 동료에게 보이는 전신을 각각 확인한다. 수영과 워치 동작은 동시에 가능해야 한다.
- 자신에게 산소 사용 / 친구에게 내밀기 / 구조받고 자세 회복의 동작을 구분한다.
- 수중 호흡, 기포, 워치 신호, 산소 경고, 에어포켓의 소리 변화를 초기부터 시험한다.
- 화면 흔들림·카메라 롤은 기본적으로 약하게 하며 민감도와 멀미 대응 옵션을 최종 범위에 포함한다.

현재 시제품의 기본 도형 캐릭터, 절차적 팔 동작, 합성 효과음은 조작 확인용이다. 최종 캐릭터 모델·리깅·애니메이션과 동등한 완성도로 취급하지 않는다. 에셋 예산 배분은 첫 시제품 평가 후 결정한다.

## 8. 기술 기준과 범위

현재 확인 환경은 Unity 6000.6.0f1, URP, Input System 1.20.0, Fusion 2.1.3, Voice 2.63 Realtime5다. SDK 설치와 컴파일 검증은 완료했지만 실제 온라인 플레이·음성 송수신 구현은 별도 작업이다. App ID 원문은 문서에 기록하지 않는다.

외부 시스템 → 기능별 파사드 → 담당 Component 호출 구조를 사용한다. 입력, 수영, 산소, 아이템, 워치, 표현을 분리한다. 네트워크 단계에서는 산소·소모품·구조 결과를 권한 있는 상태에서 검증한다. 첫 로컬 시제품의 시간·입력 처리는 이후 네트워크 시뮬레이션으로 옮길 때 별도 검증한다.

최종 플랫폼 목표는 PC / Steam이며 모바일·콘솔·WebGL 동시 지원은 현재 범위가 아니다. Fusion 동작 모드, 로비 공개 범위, 재접속과 호스트 이탈 정책은 M2 시작 전에 비교·결정한다. 유료 서비스 계약·에셋 구매·스토어 게시를 이 문서로 실행하지 않는다.

## 9. 미정 항목과 평가 질문

- 위협 생물을 넣을지 여부와 전투 필요성.
- 부활 아이템의 획득량, 에어포켓 장치 사용 제한, 탈락자의 관전 방식.
- 최종 캐릭터·장비 디자인과 사용할 모델·모션 자산.
- 네트워크 모드, 재접속·중도 참가·방장 종료 처리.
- 키 재설정, 패드, 자막·음량·멀미 옵션, 목표 사양.
- 각 챕터의 최종 경로와 모래·물살의 강도.

첫 평가에서는 수영만 해도 느낌이 괜찮은지, 워치가 잘 읽히는지, 산소 사용이 의도대로 되는지, 동굴이 어두워도 길을 판단할 수 있는지 확인한다. 다음 4인 시제품에서는 사고가 짜증보다 협동과 웃음으로 이어지는지 확인한다.
